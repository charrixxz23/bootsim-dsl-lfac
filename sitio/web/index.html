    Arquitectura
    
      
    Del texto al arranque simulado
    
      
    Un programa pasa por piezas separadas, cada una en su archivo de Python. Si el lexer, el parser o la semántica encuentran un error, el programa se rechaza y no se simula nada.
    
      
    
        
    Lexer
    corta el texto en piezas con nombre (tokens).
    
        
    Parser
    comprueba que las piezas sigan la gramática y arma el árbol.
    
        
    Semántica
    primera pasada sobre el árbol: valida sin ejecutar.
    
        
    Simulador
    segunda pasada: mueve la computadora de mentira entre estados.

      Metodología y transparencia
      
    
        
    BootSim DSL se desarrolló con apoyo de herramientas de inteligencia artificial: ChatGPT ayudó con el índice del proyecto, el diseño de la Skill de trabajo y la orquestación por fases; Claude Code desarrolló, bajo la dirección del equipo, el código, las pruebas y esta página. La revisión humana del código y de los textos está en curso, y las pruebas, aunque se pueden repetir, las diseñó la IA.
    
        
    La demostración usa Python 3.13 en el navegador; la terminal se probó con Python 3.10 y 3.12. La primera visita descarga unos 13 MB (el motor de Python). No hay licencia elegida todavía. Las tipografías (Plus Jakarta Sans, DM Sans y JetBrains Mono) usan la licencia SIL Open Font 1.1.
