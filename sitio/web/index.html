Escribe cómo arranca una computadora. Míralo arrancar.

BootSim DSL es un lenguaje pequeño hecho para un solo trabajo: describir el arranque de una PC, desde que se pulsa el botón hasta que el sistema operativo queda activo, y simularlo en texto sin tocar tu equipo real.

DSL significa «lenguaje específico de dominio»: un lenguaje que sirve para un solo tema en lugar de para todo.

    Cómo funciona
    
      
    Cinco piezas, una detrás de otra
    
      
    Un compilador no hace magia: divide el trabajo. Estas son las piezas de BootSim y el archivo de Python que hace cada una.
    
    
    
    
      
      
    1. 1
      Lexer
      Lee el texto y lo corta en piezas con nombre (los tokens): POWER_ON, el número 8, un punto y coma. Si ve algo que el lenguaje no tiene, anota el error con su línea y columna y sigue.
      lexer.py
      2. 
      
    2. 2
      Parser
      Comprueba que las piezas vengan en un orden permitido, como la gramática de una frase. Lo genera PLY, una biblioteca de Python, a partir de reglas escritas en el código.
      parser.py
      3. 
      
    3. 3
      Árbol (AST)
      El programa convertido en un árbol: cada comando es una rama y recuerda su posición en el texto. Sirve de punto de encuentro para las dos pasadas siguientes.
      ast_nodos.py
      4. 
      
    4. 4
      Semántica
      Primera pasada sobre el árbol: ¿cada variable tiene valor?, ¿los comandos van en el orden del arranque?, ¿la RAM y el disco están dentro de sus límites? No ejecuta nada.
      semantica.py
      5. 
      
    5. 5
      Simulador
      Segunda pasada: recorre el árbol y mueve una computadora de mentira entre estados. Solo cambia variables de Python: no toca discos, particiones ni firmware reales.
      simulador.py
      6. 
    
    
    
    Si el lexer, el parser o la semántica encuentran un error, el programa se rechaza y no se simula nada. Un fallo del arranque simulado (por ejemplo, RAM en cero) es distinto: el programa está bien escrito, y lo que falla es la computadora de mentira.
    
  
    

    



    
  
    
    
    
      
    El lenguaje
    
      
    Doce comandos y unas pocas reglas
    
      
    Esta tabla se lee del propio código del simulador cuando carga la página; no está escrita a mano. Cada comando solo vale en su etapa del arranque.
    
    
    
    
    ComandoArgumentosSe usa enDeja el equipo enLímites
    Disponible cuando el motor de Python termine de cargar.
    
    
    
      
    Variables y datos
    Se asignan con SET n = 8;. Hay tres tipos: entero, booleano (TRUE o FALSE) y texto entre comillas. Los comentarios empiezan con # o //.
    
      
    Decisiones y repeticiones
    IF … THEN … ELSE … ENDIF elige un camino. REPEAT 3 TIMES … ENDREPEAT repite. BEGIN … END agrupa varias sentencias. Cada estructura se cierra con su propia palabra, así que no existe el «ELSE colgante».
    
      
    Operadores
    De menor a mayor prioridad: OR, AND, NOT, == !=, < > <= >=, + -, * / y el menos unario. Los comparadores de orden no se encadenan: a < b < c es un error.
    
    
    
  
    

    



    
  
    
    
    
      
    Fidelidad
    
      
    Lo que ves es lo que se probó
    
      
    Una demostración web puede mentir con facilidad: basta con reescribir el simulador en otro lenguaje y que «se parezca». Aquí no se hace. La página usa los mismos archivos de Python y la misma versión de PLY (3.11) que la terminal. El flujo de publicación los compara y está configurado para no publicar nada si las salidas difieren.
    
    
    
    
    
      
    
        
    El informe de comparación se carga con la página.
    
      
    
      
    
        
    Cómo se comprueba
    
        
    El mismo programa se ejecuta de dos maneras: con python codigo/main.py en una terminal y con el código que corre en el navegador (Pyodide, un Python compilado a WebAssembly). Se comparan el código de salida, la salida normal y la de errores, carácter por carácter.
    
        
    Los casos son todos los programas .dsl del repositorio, variantes con errores hechas por azar repetible (siempre las mismas) y unos pocos archivos especiales (vacío, con BOM, en latin-1, inexistente…), cada uno con y sin --debug. Las cantidades exactas están en el resultado de la izquierda.
    
        
    python sitio/construir.py
node sitio/pruebas/paridad.mjs
    
        
    Límites que conviene conocer
    
        
      
          
    • El navegador usa Python 3.13; la terminal se probó con Python 3.10 y 3.12. Las salidas coinciden, pero son versiones distintas.
      • 
          
    • La página no prueba cómo la consola de Windows dibuja las tildes (eso depende de la terminal, no del lenguaje).
      • 
          
    • La primera carga baja unos 13 MB (el motor de Python); después el navegador los guarda.
      • 
          
    • Las pruebas automáticas del proyecto las diseñó la IA; el equipo todavía no las ha repetido por su cuenta.
